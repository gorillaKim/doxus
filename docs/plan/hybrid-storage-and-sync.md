# Doxus 하이브리드 스토리지 및 스마트 동기화 구현 계획

본 문서는 로컬 파일의 효율적 관리와 외부 서비스의 안정적인 검색을 위해 '참조(Reference) 및 스냅샷(Snapshot)' 하이브리드 모델을 도입하는 상세 로드맵을 기술합니다.

## 1. 개요 (Overview)
현재 Doxus는 모든 문서를 DB에 본문을 중복 저장하고 있어, 대규모 로컬 지식 베이스(Obsidian 등) 연동 시 저장 공간 낭비와 데이터 정합성 문제가 발생할 수 있습니다. 이를 해결하기 위해 로컬 파일은 오프셋 정보를 통한 실시간 참조 방식으로, 외부 API는 스냅샷 방식으로 이원화하여 관리합니다.

## 2. 핵심 아키텍처 (Core Architecture)
- **로컬 소스**: `(file_path, start_byte, end_byte)` 저장 -> 검색 시 `memmap2`로 실시간 발췌.
- **외부 소스**: `content` 본문 스냅샷 저장 -> 검색 시 DB 캐시 활용.
- **검색 랭킹**: **RRF (Reciprocal Rank Fusion)**를 통해 벡터(의미)와 FTS5(키워드) 결과 결합.
- **하이라이팅**: Rust 기반의 `aho-corasick` 고속 매칭 엔진 사용.

---

## 3. 단계별 상세 로드맵 (Phased Roadmap)

### Phase 1: 파운데이션 - DB 스키마 개편
- **목표**: 하이브리드 저장을 지원하는 데이터 구조 구축.
- **작업 내용**:
    - **V27 마이그레이션**: `chunks` 테이블에 `start_byte`, `end_byte` 컬럼 추가, `content` 필드 Nullable 전환.
    - **FTS5 최적화**: 로컬 파일 본문 비우기(`content=""`) 전략 수립.
    - `core/src/db/schema.rs` 모델 업데이트 및 `TestDb` 검증.

### Phase 2: 인덱서 - 오프셋 추적형 청커 리팩토링
- **목표**: 문서 분할 시 원본에서의 위치 정보를 정확히 추출.
- **작업 내용**:
    - `chunker.rs` 고도화: 텍스트 분할 시 슬라이싱 지점의 바이트 오프셋 계산 로직 추가.
    - `search.rs` 인덱싱 파이프라인 수정: 소스 타입(Local/External)에 따른 분기 저장 로직 구현.

### Phase 3: 엔진 - 고성능 Rust Highlighter 구현
- **목표**: DB 본문 없이도 밀리초 단위의 실시간 스니펫 생성.
- **작업 내용**:
    - `memmap2` 기반의 Zero-copy 파일 읽기 유틸리티 개발.
    - `aho-corasick`을 이용한 멀티 키워드 고속 하이라이팅 (`<b>` 태그 삽입).
    - **Unicode Safety**: 한글 등 멀티바이트 문자 경계에서의 안전한 커팅 보장.

### Phase 4: 통합 - 하이브리드 검색 및 RRF 적용
- **목표**: 사용자에게 일관된 검색 및 발췌 결과 서빙.
- **작업 내용**:
    - `SearchEngine` 내부의 `snippet()` 호출을 새 Highlighter 모듈로 교체.
    - 검색 결과 리스트에 대해 RRF 알고리즘을 적용하여 랭킹 최적화.
    - 발췌된 텍스트의 정합성 재검증(`Verification`) 단계 추가.

### Phase 5: 서비스 - 스마트 배경 동기화 (Idle Sync)
- **목표**: 리소스 최적화 및 최신성 유지.
- **작업 내용**:
    - Tauri `WindowEvent::Focused` 및 `tauri-plugin-idle` 연동.
    - 저우순위 스레드를 통한 백그라운드 인덱싱 (UI 반응성 확보).
    - 외부 서비스 증분 동기화(`Events API`) 연동.

---

## 4. 검증 및 품질 관리 (QA)
- **단위 테스트**: `char_indices` 기반의 유니코드 오프셋 정확도 집중 테스트.
- **성능 테스트**: 100MB 이상 대용량 파일에서의 스니펫 생성 지연 시간 측정 (목표: < 10ms).
- **용량 테스트**: 마이그레이션 전후 DB 파일 크기 비교 (목표: 80% 이상 절감).
