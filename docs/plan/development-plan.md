# 🚀 Doxus 잔여 작업 개발 계획 (Work Plan)

본 문서는 현재 Doxus 서비스의 구현 현황을 바탕으로, 완전히 구현되지 않은 기능들을 효과적으로 마무리하기 위한 단계별 작업 계획(Roadmap)입니다. 코어 엔진과 기본 플러그인 구조는 대부분 완성(Phase 0~8)되었으므로, **백엔드 고도화 및 UI/UX 바인딩, 안정화**에 초점을 맞춥니다.

---

## 🛑 Phase 1: 백엔드 코어 버그 수정 및 아키텍처 정리 (우선순위: 매우 높음)

**목표:** 코드 부채를 해결하고, 실제 동작 과정에서 발생할 수 있는 잠재적 크리티컬 버그(인증 무효화 등)를 예방합니다.

* **[ ] Confluence 플러그인 토큰 갱신 플로우 완성**
  * `crates/plugins/confluence/...` 내부에서 구현된 API `refresh_token()` 로직이 실제 HTTP 문서 `fetch_changes()` 등의 호출 전에 자동으로 검증 및 수행되도록 파이프라인(가드 로직) 추가.
* **[ ] `mcp-server` 유지보수성 확보**
  * 현재 2,500줄 이상 비대해진 `crates/mcp-server/src/main.rs` 로직을 독립적인 모듈들 및 `lib.rs`로 완전히 분리. 도구(Tools)별 단위 테스트 작성 체계 구축.
* **[ ] 문서 쓰기(Write) 권한 제어 구조 확립**
  * `DocSource` Trait 내에 `supports_write()` 기능을 명시적으로 구현 및 적용. 외부 프로젝트 연동 시 해당 프로젝트가 쓰기를 지원하는지에 따라 애플리케이션의 워크스페이스 구조 동작 제어. (예: 템플릿으로 새 파일 생성 제어)

---

## 🧠 Phase 2: 검색 품질 고도화 및 문서 맥락 파악 강화 (우선순위: 높음)

**목표:** 에이전트와 사용자가 단순 벡터/텍스트 매칭을 넘어, '문서의 구조와 관계'를 파악할 수 있도록 데이터를 정제합니다.

* **[ ] 문서 계층 구조 트리 (`heading_path`) 파싱 적용**
  * 마크다운 문서 인덱싱 과정에 헤딩(`H1 > H2`) 파서를 적용하여 `Chunk.heading_path` DB 컬럼에 저장.
  * 검색 결과 및 MCP 에이전트 반환 시 "형제 섹션" 및 "부모 헤딩" 등의 맥락(Context)을 함께 제공하여 AI 성능 향상.
* **[ ] 링크 파서 고도화 (노드 ↔ 터널 링크)**
  * 옵시디언 등 문서 본문에 삽입된 `[[문서명]]`(노드 링크) 및 `[[프로젝트::문서명]]`(터널 링크 - 외부 소스 간 참조) 구문을 분석하는 파서 개발.
  * 파싱된 링크 정보를 `document_links` DB 테이블에 직접 라우팅하여 추후 Graph View 기능 지원.
* **[ ] 사서 에이전트 메모리 스택 적용 (MemPalace 모델)**
  * 무조건 전체 DB를 검색하던 비효율 구조를 개편, L0(기본 워크스페이스 정보), L1(최근 읽은 문서), L2/L3 등 단계별로 LLM 컨텍스트를 호출하도록 에이전트 인출 로직 분리.

---

## 🖥 Phase 3: 프론트엔드 및 마켓플레이스 UI 바인딩 (우선순위: 보통)

**목표:** 데스크톱 UI 앱(Tauri+React) 상의 Mocking 데이터를 제거하고 실제 백엔드 로직과 이어줍니다.

* **[ ] 데스크톱 마켓플레이스 통합 연동**
  * `MarketPage` 상의 하드코딩된 `MOCK_PLUGINS` 변수를 제거하고 백엔드의 `RegistryClient` 연결.
  * 실제 .wasm 바이너리 다운로드 직후 -> 서명(ed25519) 무결성 자동 검증 -> 로컬 디렉토리 이관 및 플러그인 DB 등록에 이르는 E2E 파이프라인 마무리.
  * Semver 버저닝 관리 지원 추가.
* **[ ] 데스크톱 UI 반응성 및 영속화 개선**
  * `SettingsPage` 내부 사용자 설정값을 백엔드 파일 시스템에 영속화 시키는 Tauri Command 연결 수정.
  * 사용자 볼트(Vault) 및 플러그인의 문서를 동기화할 때, `DashboardPage`에 실시간 진행 상태 이벤트 모델(Tauri event) 완벽 구축.

---

## 🛠 Phase 4: 배포 및 인프라 파이프라인 고도화 (우선순위: 보통 ~ 낮음)

**목표:** Doxus 생태계의 오픈 소스 배포 자동화를 구성합니다.

* **[ ] 플러그인 배포 파이프라인 자동화 (CI/CD)**
  * GitHub Actions 등을 통해 Official WASM 플러그인 빌드 및 레지스트리 자동화 등록, 체크섬 및 서명 자동 발급 환경 구성.
* **[ ] 크로스 플랫폼 데스크톱 앱 최적화**
  * Chunking 튜닝 및 초기 Load 성능 최적화(Lazy 로드). Tauri 내부 IPC 오버헤드 측정 및 프로파일링.
